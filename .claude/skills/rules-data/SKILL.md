# Rules and faction data

Step lists live in `AI_GUIDE.md` (how to add each kind of rule) and `docs/EDITING.md` (which file holds what). This
skill is the checklist around them.

## Inventory first

1. Find the card text: `public/data/factions/<ID>.json` (generated; never edit it by hand).
2. Find what already runs for it, in this order:
   - `data/abilities/<ID>.json` (key: the name, or `Name@Datasheet`), `data/stratagems/<ID>.json` (key: the card
     name in capitals, or `NAME@Detachment`), `data/detachment-rules.json`;
   - a faction module `src/factions/<faction>.ts` (`grep -n "<rule name>" src/factions/*.ts`);
   - the text reader (`src/rules-engine/abilityText.ts`, and stratagem card parsing in `stratagems.ts`), which may
     already turn the text into effects.
3. Read its line in `docs/RULES_STATUS.md` (works, partial, text only, bug).
4. Look for the same rule in another faction: copy its data shape rather than inventing one (`grep -rn "<effect key>" data/abilities`).

## Deciding

- Data before code. An `Effect` key, an `act` with a trigger, or a condition in `cond()` covers most rules.
- Code only when the rule keeps state (tokens, marks, a pool of dice): a module in `src/factions/`, registered in
  `src/factions/index.ts` through a hook from `ARCHITECTURE.md`. Never import a faction from `src/engine/` or
  `src/rules-engine/` (`src/engine/layers.test.ts` enforces it).
- A new condition or trigger is a case in `cond()` / the activation list, kept a pure function of the game state.
- Wrong datasheet numbers go in `data/overrides/<ID>.json`, then `npm run data`.

## Verify

- `npx vitest run src/engine/rulesData.test.ts`: unknown keys, conditions and triggers fail it.
- A test in the faction's test file that builds the unit and checks the number the rule changes (Hit, Wound, OC,
  Move...). For an `Effect`, the change must show in the engine (see `verify`, "Effect fields").
- For a faction-wide change, a seeded bot-vs-bot game with that faction plays to the end.
- Update `docs/RULES_STATUS.md` when a rule's grade changes.

## Pitfalls seen before

- A defensive stratagem worded "just after an enemy unit has selected its targets" (Wrath of the Doomed) was never
  offered to a player: only `react: "targeted"` cards were, and that moment was sync-only. Now `reactionOffers` also asks
  cards with `bot: "defend"` and that WHEN text, in their own phase; the attack stays open while the window is up
  (`handleReact`, `botAttack`, `autoShoot`). The bot is not asked through this path.
- A rule with `"status": "auto"` and no `effects` or `act` does nothing.
- A field on a timed effect is not always read the same way as on an ability (keywords such as MOBILE are only
  applied from abilities; use `throughTerrain` for a timed effect).
- Factions whose data was generated by script have more wrong numbers: check a few against the card when touching them.
- Changing the order of dice rolls changes every seeded game; if you do it on purpose, say so in the commit.
- In `scripts/build-data.mjs`, distinguish the replaced weapon from the gained item: for text such as
  "the model's lasgun is replaced with 1 laspistol", parse only the right-hand item as a choice.
- Do not trust every exported army-rule row to belong to its faction. The data export repeats Combat Doctrines for
  non-Space-Marine factions; compare the rule's faction keywords and add a regression test before regenerating
  `public/data/factions/`.
- A new phase-end activation trigger must be wired into both the turn-loop end-phase path and `AUTO_ONLY`; data
  validation alone only proves the trigger name is accepted. Test the actual reaction window through `endPhase`.
- `omniScrambler` can block Reserve placement in `game.ts` while the board still shows only the normal 9" ring;
  compare validation with the UI guide and use each enemy's effective `unitFlags` range.
- A stratagem window can open at the right moment and still offer the wrong targets: Fire Overwatch opened at the end
  of the Movement phase and let any enemy within 24" be shot, though only a unit that moved or was set up may be.
  Check the TARGET line as well as the WHEN line, in the engine (`overwatchTargets`), the player's target list and the
  bot.
- A rule that "heals" restores wounds only to a damaged model (`heal` in `activations.ts`); with every model at full
  wounds it does nothing visible. That is not a bug in the rule (checked for Sorcerous Invigoration).
- A Ritual that pauses for a decision after its first dice roll must keep that roll in game state so reload preserves
  the decision. Undo should reverse the roll and return to the state before the attempt; resolve doubles/triples with
  one Perils event after the final dice are chosen.
- Thousand Sons Cabal of Sorcerers (official FAQ, pasted by the owner 18 Nov 2026): the player rolls the first dice, then decides whether to Channel the Warp; the D3 mortal wounds for a double or triple come only when the model Channelled (`resolveRitualTest`, `testOdds` in `rituals.ts`); Rituals are attempted one model and one Ritual at a time, not sequenced up front.
- A test the game rolls in one go that a player may want to Command Re-roll (Dark Pact, Malefic Surge, Deadly Vectors; hazard rolls open the same window from `hazardTest`, with the `hz` field) is split in two: the roll, then a `crTest` window (`factions/crTests.ts`, owner decision: the player chooses, the game does not spend the CP for a person) and a `finish...` function registered with `onCrTestDone`. Bots and automatic rules skip the window and re-roll by themselves (`crTest` in `state.ts`). A new such roll: open the window after rolling, put everything that follows in the finisher.
- A stratagem the game itself would use at a moment of an army rule (Genestealer Cults: Evasive Vanguard and the other marker savers, Lying in Wait, The Downtrodden Rise) is paid by itself only for a bot. For a person it opens a `cpAsk` window (`answerCpAsk` in `cult.ts`): Use (NCP) or No. A new one of these: ask, never spend a person's CP (owner, 19-20 Nov 2026).
- An enhancement could not be picked (C'tan Shards in Pantheon of Woe, 20 Nov 2026): the builder refused every EPIC HERO, but the card says "C’tan Shard of the Deceiver model only". `enhancementFits` now returns the names the line allows; an EPIC HERO may take an enhancement that names its datasheet (`enhancementOptions` and `validateList`). Other readers added: "X model with the Y ability only", a plural keyword for its singular (SCOUT SENTINEL), a weapon condition is no keyword, and a detachment that makes a unit a CHARACTER counts it as one. `army.test.ts` fails when any enhancement of any detachment cannot be taken by some datasheet; the one known gap is Parasitic Woe-Reaper (CONTAGION ENGINE: no datasheet carries that keyword in the data).
- A stratagem TARGET written in ordinary capitals ("One Thousand Sons Psyker unit from your army") was never read, so the card offered any unit (Infernal Fusillade on a Defiler and a Rhino, 20 Nov 2026). `stratTargetOk` now reads a simple "One X Y unit" line (`targetPhrase`, `phraseCovered`); a phrase that is no keyword of any datasheet (Attached, Soul Forge, Armoured Skirmisher, War Dog Character) is listed in `UNREADABLE_TARGET` and not filtered. `stratTarget.test.ts` fails when a readable line fits no datasheet.
- Making an engine action refuse (return an error text) needs every bot caller to treat the refusal as 'not done': `useCounteroffensive` refused a unit a stratagem had already targeted and the bot asked again for ever (a Thousand Sons game never ended). Candidate lists must use the same check as the action.
- Wargear text from Wahapedia: a weapon whose name has "and" or a comma in it ("Knives and Fists", "Monstrous bonesword
  and lash whip", "Bone cleaver, lash whip and rending claws") is one item; `items()` in `scripts/build-data.mjs` keeps
  the datasheet's own weapon names whole. "one of the following: 1 X and 1 Y, 1 Z and 1 Y" without bullets is a list of
  choices. Before the fix (21 Nov 2026) such options never matched the loadout and swapped nothing.
- The pack/Wahapedia hybrid (`wargearFrom: 'wahapedia'`) takes Wahapedia's wargear when it has more choices than the
  pack: a parser fix that adds choices can move more units over (Death Company Marines, Deathwing Terminator Squad and
  Fortis Kill Team moved on 21 Nov 2026). Compare the list of hybrid units before and after `npm run data`.
