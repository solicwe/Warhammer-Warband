# Rules status

Which rules the game actually runs, faction by faction. Generated from an audit of the rule data against the engine code; re-run it after changing `data/`.

## How a rule is graded

- **Works**: the rule has executable data (effects, triggers, choices) and every condition, trigger and key in it is one the engine reads, or the rule is implemented in a faction module.
- **Partial**: the main effect runs; the rest is left to the player (shown on the rule card).
- **Text only**: the rule is shown with its text but nothing in the engine does it. The player has to resolve it by hand, and the bot never uses it.
- **Bug**: there is data for it, but it uses a key or trigger the engine does not have, so it silently does nothing.

"Works" means the rule runs. It does not prove the numbers match the card. A hand check of 30 random "Works" abilities found 16 exactly right, 6 close (a missing weapon filter or condition) and 8 wrong (two of those are fixed in this change); the wrong ones were in the factions whose data was generated by script (see "Accuracy" below).

## Accuracy

Hand-written factions (SM, ORK, CSM, WE, EC, TS, DG, AC, QI, QT, AoI) were checked rule by rule when they were added. The other factions were filled in by generator scripts (`scripts/gen-*`), and many of their entries only carry the card text with `"status": "auto"` and no effect. Those show as automated in the app but do nothing; they are counted as "text only" here.
